✍️ Ingénierie de prompt

Structure d'un bon prompt :

1. Contexte : Situation, rôle, objectif

2. Tâche : Ce que vous voulez obtenir

3. Format : Structure attendue

4. Contraintes : Limitations, exigences

Exemple :

"Tu es un Product Owner expérimenté. Écris une user story pour une fonctionnalité de connexion utilisateur dans une application e-commerce, en suivant le format INVEST."

📝 Exercice 1 : Méthode ACTF

🎯 Objectif

Apprendre à structurer un prompt efficace avec la méthode ACTF

Acteur + Contexte + Tâche + Format

⏱️ Durée : 20 minutes

📊 Scénario

User story pour "notification de rappel avant échéance" dans une app de gestion de tâches

📝 Exercice 1 : Étapes

Étape 1 - Prompt basique (mauvais exemple)

"Écris une user story pour les notifications"

Étape 2 - Transformez avec ACTF (10 min)

A - Acteur : "Tu es un Product Owner senior avec 8 ans d'expérience..."

C - Contexte : Décrivez le produit, les utilisateurs cibles

T - Tâche : Que doit faire précisément l'IA ?

F - Format : INVEST ? Avec critères d'acceptation ? En Gherkin ?

Étape 3 - Testez (5 min)

Copiez votre prompt dans ChatGPT/Claude et observez la qualité

💡 Exercice 1 : Débrief

Points clés à retenir

  • Un bon prompt = précision maximale du contexte
  • ACTF transforme un résultat vague en résultat utilisable
  • Le temps investi dans le prompt se récupère x10

Questions de réflexion

  • Quelle structure a donné le meilleur résultat ?
  • Combien d'itérations avant satisfaction ?

🔁 Exercice 2 : L'art de l'itération

🎯 Objectif

Maîtriser l'itération de prompts pour améliorer progressivement un résultat

⏱️ Durée : 20 minutes

📊 Problème

User story générée avec critères d'acceptation trop vagues et non testables

🔁 Exercice 2 : Itérations successives

Itération 1 - Préciser les critères (6 min)

"Réécrire les critères d'acceptation en format Gherkin (Given/When/Then) pour qu'ils soient testables par l'équipe QA."

Itération 2 - Ajouter contraintes (6 min)

"Ajoute 3 notes techniques concernant : canal de notification, timing de déclenchement, customisation utilisateur"

Itération 3 - Compléter métriques (6 min)

"Ajoute une section 'Métriques de succès' avec 3 KPIs mesurables"

💡 Exercice 2 : Débrief

Points clés à retenir

  • Le premier résultat n'est JAMAIS le bon
  • L'itération est normale et souhaitable
  • Chaque itération améliore la précision

Questions

  • Combien d'itérations avez-vous faites ?
  • Quand estimez-vous le résultat "production-ready" ?

🎯 Exercice 1 : RICE Framework

🎯 Objectif

Prioriser 6 features avec un framework data-driven

RICE = (Reach × Impact × Confidence) / Effort

⏱️ Durée : 20 minutes

📊 Contexte

Plateforme SaaS de gestion de projet - 5000 utilisateurs

6 features candidates, capacité pour seulement 3

🎯 Exercice 1 : Les 6 features

A - Intégration Slack

Notifications pour tâches importantes

B - Mode hors-ligne

Consulter/éditer sans connexion

C - Templates de projets

Bibliothèque 20+ templates prêts (Agile, Waterfall, Marketing)

D - Dashboard exécutif

Vue consolidée KPIs pour dirigeants

E - Intégration Jira bidirectionnelle

Synchronisation complète pour équipes hybrides

F - Gestion de ressources

Planification et allocation (personnes, matériel)

🎯 Exercice 1 : Prompt RICE

Prompt à utiliser

Tu es un expert en priorisation produit utilisant le framework RICE.

Contexte : Plateforme SaaS, 5000 utilisateurs, 4 développeurs

Pour CHAQUE feature, estime :

  • REACH : Utilisateurs touchés/trimestre (justifié)
  • IMPACT : 0.25=Minimal, 0.5=Faible, 1=Moyen, 2=Élevé, 3=Massif
  • CONFIDENCE : 50%=0.5, 80%=0.8, 100%=1.0
  • EFFORT : Personnes-mois (backend, frontend, QA)
  • SCORE RICE = (R × I × C) / E

Fournis TABLEAU avec classement et recommande les 3 features prioritaires.

ROI mesuré

  • Temps : 2-3h débat → 15 min = 90% gain

  • Traçabilité : 0% → 100%

🔍 Exercice 2 : Framework SWOT

Structure SWOT

STRENGTHS (Forces internes)

Ce que vous maîtrisez : équipe, produit, tech

WEAKNESSES (Faiblesses internes)

Vos points faibles : compétences manquantes, contraintes

OPPORTUNITIES (Opportunités externes)

Marché, tendances, nouveaux segments

THREATS (Menaces externes)

Concurrence, risques, évolutions du marché

Interne vs Externe

Interne = Sous votre contrôle | Externe = Hors contrôle
